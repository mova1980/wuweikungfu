# 🥋 وو وی کونگ فو | Wu Wei Kung Fu

وب‌سایت بین‌المللی سه‌زبانه (فارسی/انگلیسی/چینی) برند **وو وی کونگ فو** به همراه پنل مدیریت کامل (CMS)، بر پایهٔ چشم‌انداز هنری **«میدان انرژی زنده»**.

---

## ⚡ اجرای سریع

```bash
npm install
npm run dev        # http://localhost:3000
```

- سایت به‌صورت خودکار به `/fa` هدایت می‌شود. زبان‌ها: `/fa` (RTL)، `/en`، `/zh`
- **پنل مدیریت:** `/admin` — رمز عبور پیش‌فرض: `wuwei2026`
  (با متغیر محیطی `ADMIN_PASSWORD` قابل تغییر است)

## 🏗 معماری

| لایه | فناوری |
|---|---|
| فریم‌ورک | Next.js 14 (App Router) + TypeScript |
| استایل | Tailwind CSS + دیزاین‌سیستم اختصاصی (متغیرهای CSS) |
| انیمیشن | Canvas API (میدان انرژی)، IntersectionObserver، CSS keyframes |
| چندزبانه | Middleware اختصاصی + دیکشنری‌های JSON (`src/dictionaries`) |
| دیتابیس | فایل‌های JSON در `data/` (قابل ارتقا به PostgreSQL/Prisma) |
| CMS | پنل اختصاصی Next.js در `/admin` + REST API در `/api/admin/*` |
| احراز هویت | کوکی HttpOnly + گارد Middleware |

## 🎨 ویژگی‌های هنری پیاده‌سازی‌شده

- **میدان انرژی زنده** (`EnergyField.tsx`): ذرات طلایی/قرمز که هنگام ورود مانند براده‌های فلزی از حاشیه به مرکز جذب می‌شوند، ردیاب نور طلایی «چی» زیر ماوس، و خطوط میدان بین ذرات.
- **حالت شاگرد** (`ScrollMood.tsx`): اسکرول سریع → حالت «تهاجمی» (قرمز، انیمیشن سریع)؛ اسکرول آرام → حالت «مراقبه» (آبی نیلی، انیمیشن کند). نشانگر زندهٔ حالت در گوشهٔ صفحه.
- **دیالوگ سختی و نرمی:** بخش‌های رزمی با گرید شکسته و لبهٔ تیز (`hard-edge` با clip-path) و بخش‌های چی‌گونگ با منحنی‌های ارگانیک (`soft-edge`).
- **روایت سه‌لایه:** سختی → تکنیک → سکون در صفحهٔ اصلی، با نوار ابریشمی متحرک حروف چینی.
- **میکرواینتراکشن‌ها:** دکمهٔ CTA با موج انرژی دنبال‌کنندهٔ ماوس، تایپ‌رایتر، شمارنده‌های متحرک، کشش تایپوگرافی روی هاور (`stretch-word`)، دارک/لایت مود.

## 🛠 پنل مدیریت (CMS)

مسیر: `/admin` — تمام بخش‌ها سه‌زبانه (FA/EN/ZH):

1. **داشبورد:** آمار همهٔ بخش‌ها + دانلود پشتیبان کامل JSON
2. **مقالات / تکنیک‌ها / ویدئوها / رویدادها / محصولات / نظرات:** CRUD کامل با فرم‌ساز خودکار چندزبانه
3. **پیام‌ها:** صندوق پیام‌های فرم تماس (خوانده/حذف)
4. **ثبت‌نام‌ها:** مدیریت ثبت‌نام کلاس‌ها (تأیید/رد/حذف)
5. **محتوای سایت:** آمار صفحهٔ اصلی، اطلاعات تماس، تایم‌لاین، افتخارات، مربیان، کمربندها

## 🚀 استقرار (Deployment)

### Vercel (توصیه‌شده)
1. مخزن را به Vercel متصل کنید — بیلد بدون تنظیم اضافه انجام می‌شود.
2. چون فایل‌سیستم Vercel فقط‌خواندنی است، برای ذخیرهٔ داده‌های پنل ادمین یک دیتابیس **Upstash Redis** (رایگان) از تب Storage اضافه کنید. متغیرها به‌صورت خودکار ست می‌شوند:
   - `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` (یا `KV_REST_API_URL`/`KV_REST_API_TOKEN`)
   - لایهٔ داده (`src/lib/db.ts`) به‌صورت خودکار بین Redis و فایل JSON سوییچ می‌کند؛ اولین‌بار از seedهای باندل‌شده مقداردهی می‌شود.
3. سایر متغیرهای محیطی:
   - `ADMIN_PASSWORD` — رمز پنل مدیریت (حتماً تغییر دهید)
   - `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL` — دستیار هوشمند (اختیاری؛ از پنل ادمین هم قابل تنظیم است)

### سرور شخصی (VPS)
```bash
npm run build && npm start          # داده‌ها در data/*.json ذخیره می‌شوند
```
- پشت Nginx با Let's Encrypt قرار دهید؛ هدرهای CSP/HSTS را در Nginx اضافه کنید.

## 🤖 دستیار هوشمند (استاد همراه)

ویجت چت شناور در همهٔ صفحات (سه‌زبانه) با شخصیت «دکترای فیزیولوژی و تغذیه ورزشی + استاد کونگ فو و چی‌گونگ».
- Endpoint: `/api/chat` — سازگار با هر سرویس OpenAI-compatible (OpenAI، OpenRouter، Groq، DeepSeek، AvalAI، Ollama و…)
- پیکربندی: متغیرهای محیطی `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` **یا** پنل ادمین → محتوای سایت → «دستیار هوشمند»
- تاریخچهٔ گفتگو در sessionStorage مرورگر کاربر نگه‌داری می‌شود؛ سمت سرور چیزی ذخیره نمی‌شود.

## 💳 درگاه پرداخت

فرآیند کامل: سبد خرید (با ذخیره در localStorage) → فرم اطلاعات خریدار → ایجاد سفارش سمت سرور (قیمت‌ها از دیتابیس محاسبه می‌شود) → درگاه → تأیید/لغو → صفحهٔ نتیجه با کد پیگیری → مدیریت در پنل ادمین.

- **حالت آزمایشی (پیش‌فرض):** درگاه شبیه‌سازی‌شدهٔ داخلی در `/{locale}/pay/{orderId}` — بدون برداشت واقعی.
- **حالت زرین‌پال (واقعی):** در پنل ادمین → «محتوای سایت» → بخش «درگاه پرداخت»، حالت را روی زرین‌پال بگذارید و مرچنت‌کد ۳۶ رقمی را وارد کنید. سیستم از API نسخهٔ ۴ زرین‌پال (request/StartPay/verify) استفاده می‌کند و کال‌بک در `/api/payment/callback` تأیید می‌شود.
- **مدیریت سفارش‌ها:** `/admin/orders` — فیلتر وضعیت، جزئیات سفارش، تغییر وضعیت (پرداخت‌شده/ارسال‌شده/لغو)، مجموع درآمد تأییدشده.

## دیتابیس Supabase (پیشنهادی برای Vercel)

لایه ذخیره‌سازی به‌ترتیب اولویت: **Supabase → Upstash Redis → فایل‌های محلی `data/`**

اتصال به Supabase:
1. در [supabase.com](https://supabase.com) یک پروژه بسازید.
2. در **SQL Editor** این را اجرا کنید:

```sql
create table if not exists public.collections (
  key        text primary key,
  data       jsonb not null default '[]'::jsonb,
  updated_at timestamptz not null default now()
);
alter table public.collections enable row level security;
```

3. از **Settings → API** مقدار `Project URL` و `service_role` key را بردارید و به‌عنوان متغیر محیطی تنظیم کنید:

```
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJhbGci...
```

- کلید `service_role` فقط سمت سرور استفاده می‌شود و هرگز به مرورگر نمی‌رود؛ RLS روشن است و anon دسترسی ندارد.
- بار اول که سایت بالا بیاید، داده‌های فعلی (Redis/فایل/seed) **به‌صورت خودکار** به جدول `collections` منتقل می‌شوند (کلیدهایی مثل `wuwei:content`).
- اگر قبلاً Upstash داشته‌اید، متغیرهایش را نگه دارید تا به‌عنوان رپلیکا هم‌زمان بمانند؛ هر وقت مطمئن شدید می‌توانید حذفشان کنید.
